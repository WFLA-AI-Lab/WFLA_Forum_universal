# 前后端契约与待补功能

本次联调只使用仓库中已经存在的认证、邀请、内容、互动、通知及管理 API，另为首页新增 `GET /api/v1/feed`。以下原始校园身份需求尚无对应后端字段或规则，前端没有伪造实现：

| 需求 | 当前后端 | 建议的后续契约 |
| --- | --- | --- |
| `admin / teacher / student` | `owner / admin / moderator / member` | 明确教师是独立角色还是 `moderator` 的身份属性；保留 `owner` 超级管理员。 |
| 教师可发邀请码 | 当前仅 admin/owner 可创建 | 确认教师范围和配额，再扩展 `POST /invitations` 权限与审计。 |
| 绑定真实学生 | 只有姓名与毕业年份 | 用受保护的学生档案/花名册匹配，不在公开用户 API 暴露完整学号。 |
| 八位学号、入学日期、1–8 班 | 数据库和注册 API 均无字段 | 增加迁移、唯一性和格式校验、学生身份核验流程；定义留级/转班处理。 |
| 高中首批开放、年级自动更新 | 目前只展示毕业届别 | 以入学日期和学年切换日计算年级，并处理转班、休学及毕业边界。 |

实现顺序：先定角色/档案模型与隐私边界 → 数据库迁移 → 后端验证和权限测试 → 前端注册/资料页 → 端到端回归。避免只在前端做八位学号或年级校验，否则不能建立可信的身份绑定。
